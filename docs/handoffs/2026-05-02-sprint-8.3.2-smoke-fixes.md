## Mevcut durum — yapılanlar

### Sorun 1 — Report download 401 fix (kök neden: typo)

`packages/imga-web/src/app/(authenticated)/reports/page.tsx:downloadReport`'ta `localStorage.getItem("imga.access_token")` kullanılıyordu — ama tokenStorage helper'ı `imga_access_token` (alt çizgi, nokta değil) anahtarını kullanır. Sessizce boş Authorization header'ı gönderilip 401 alınıyordu.

Fix: `tokenStorage.getAccessToken()` helper'ına geçildi + token yoksa kullanıcıya "Oturum süresi dolmuş" toast'u gösteriliyor.

### Sorun 2 — Modal 3-step flow

Single-screen modal yerine artık explicit 3 adım:

- **Adım 1**: Rapor tipi (comprehensive / reviews_only / tickets_only) + format (xlsx / csv)
- **Adım 2**: Tarih aralığı + hızlı seçim (bu ay / geçen ay / bu çeyrek). 90 gün sınırı inline uyarı.
- **Adım 3**: Önizleme — `POST /tenants/me/reports/estimate` çağrısı ile tahmini satır + süre + tip/format/aralık özet, "Üret" butonu.

Yeni endpoint: `POST /tenants/me/reports/estimate` — dry-run. Aynı validation (90 gün / 50K satır) ama row insert YOK. 400 path'i Step 2'de inline error gösterir, Step 3'e geçirmez. `useEstimateReport` hook'u + `ReportEstimateResponse` tipi eklendi.

"Geri" butonu önceki adıma döner; "İptal" tüm modal'ı kapatır.

### Sorun 3 — Invitation token (handoff)

Lokal kod review'i temiz görünüyor: token URL-safe, hash deterministic, preview SELECT-only. Bug üretim DB'sinin durumuna bağlı: row yok mu / accepted_at ön-tüketim mi / expires_at TTL bug mu.

Ayrı handoff: [`2026-05-02-invitation-token-debug.md`](./2026-05-02-invitation-token-debug.md). 3 SQL/log teşhis komutu var, sunucu agent çalıştırıp Cevap'a yapıştırırsa kök neden netleşir, fix tek satır.

### Sorun 4 — Test fixture

`tests/conftest.py` `batch_client` fixture'ı `app.state.report_worker_context` set etmiyordu → `tenant_reports.py` route handler `request.app.state.report_worker_context` okuyunca AttributeError → 6 test KeyError.

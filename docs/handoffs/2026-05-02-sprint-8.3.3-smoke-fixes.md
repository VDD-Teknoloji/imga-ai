## Tanı + Fix özeti

### Sorun 1 — Backend 500 (KRİTİK)

**Kök neden:** `analytics_service.py` row dataclass'ları `slots=True` ile tanımlı; `__dict__` özelliği yok.

```python
@dataclass(frozen=True, slots=True)
class SentimentDistRow:
    label: str
    count: int
    ...
```

`tenant_analytics.py` route'u Pydantic projeksiyonunda `**row.__dict__` kullanıyordu → ilk satıra erişimde `AttributeError`.

**Fix:** `dataclasses.asdict()` (slots korunur, doğru API). Tüm 9 occurrence değiştirildi (`row.__dict__`, `result.__dict__`, `result.stats.__dict__` dahil).

**Doğrulama:** Test compose lokal koşturuldu, **54/54 passed** (8 analytics testi dahil) — `7b12c1a`.

### Sorun 2 — Frontend defensive coding

`/insights` sayfası backend 500'lerine karşı sessizdi:

- Error vs empty state aynı "veri bulunamadı" mesajıyla çakışıyordu
- Chart wrapper'ı yoktu — tab değişiminde Recharts ResponsiveContainer 0 dimension okuyup `width(-1) height(-1)` warning basıyordu
- Date picker `onChange` her keystroke'ta URL'e yazıyordu → invalid date string → `new Date(...).toISOString()` race condition

**Fix:** `1d4c8e9`

- `<ChartFrame>` shared helper: `error → ErrorMessage`, `loading → Spinner mesajı`, `empty → empty mesajı`. Hepsi `min-h-[Npx]` wrap'inde, böylece Recharts container fresh tab mount'unda non-zero dimension okuyor.
- Date picker'lar local `useState` ile besleniyor; URL commit `onBlur`'da ve `Number.isNaN(d.getTime())` ile validate sonrası. Tutarsız onaylama davranışı bu race ile çakışıyordu.

## Round 2 — UX bugs (smoke test sonrası)

Browser smoke test büyük ölçüde başarılı: 7 endpoint 200, charts render. İki UX bug kaldı, ikisi de tek kök nedene düştü.

### Bug 1 — Tab geçişi refresh sonrası no-op

**Senaryo:** `/insights?tab=cross&date_from=2026-04-01T00:00:00.000Z` URL'ine refresh sonrası gelinince başka tab'a tıklamak hiçbir şey yapmıyordu.

**Kök neden:** `URLSearchParams` ISO datetime'daki `:` karakterini `%3A`'ya encode ediyordu, `.000Z` aynı kalıyordu. `router.replace` çağrısında yeni querystring re-emit edildiğinde Next.js 16'nın soft-nav diff'i URL'yi current'la aynı görüp navigasyonu sessizce drop ediyordu. Bu yüzden `useSearchParams` güncellenmiyor, `tab` değeri eski kalıyor, base-ui Tabs prop değişikliği görmediği için aktif tab değişmiyordu.

### Bug 2 — Date picker -1 gün (timezone)

**Senaryo:** Kullanıcı "Başlangıç" date input'a 04.04.2026 seçip blur → input 03.04.2026 oluyordu.

**Kök neden:** `new Date("2026-04-04T00:00:00")` local time olarak parse edildi → İstanbul'da `2026-04-04T00:00:00+03:00`. `toISOString()` UTC'ye çevirdi → `2026-04-03T21:00:00.000Z`. URL'e bu ISO yazıldı. FilterBar `slice(0, 10)` ile "2026-04-03" üretip input'a verdi → bir gün geri.

### Tek fix

İki bug ortak köke düştü: ISO datetime URL'de tutmak. Çözüm URL'de **YYYY-MM-DD**: native `<input type="date">`'in zaten ürettiği/tükettiği format. Hook katmanı API'ye göndermeden önce local-midnight ISO'ya çeviriyor, böylece "April 4" → "April 4 00:00 user-timezone" semantiği korunuyor.

Bonus: tab navigasyonu artık Next.js 16 docs'taki kanonik pattern'i kullanıyor — `usePathname()` + `router.push`. Soft-nav diff temiz query string üzerinde çalıştığı için Bug 1 de kapanıyor.

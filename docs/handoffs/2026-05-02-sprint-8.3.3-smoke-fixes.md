## Tanı + Fix özeti

### Sorun 1 — Backend 500 (KRİTİK)

**Kök neden:** `analytics_service.py` row dataclass'ları `slots=True` ile tanımlı; `__dict__` özelliği yok.

```python
@dataclass(frozen=True, slots=True)
class SentimentDistRow:
    label: str
    count: int
    ...
```

`tenant_analytics.py` route'u Pydantic projeksiyonunda `**row.__dict__` kullanıyordu → ilk satıra erişimde `AttributeError`.

**Fix:** `dataclasses.asdict()` (slots korunur, doğru API). Tüm 9 occurrence değiştirildi (`row.__dict__`, `result.__dict__`, `result.stats.__dict__` dahil).

**Doğrulama:** Test compose lokal koşturuldu, **54/54 passed** (8 analytics testi dahil) — `7b12c1a`.

### Sorun 2 — Frontend defensive coding

`/insights` sayfası backend 500'lerine karşı sessizdi:

- Error vs empty state aynı "veri bulunamadı" mesajıyla çakışıyordu
- Chart wrapper'ı yoktu — tab değişiminde Recharts ResponsiveContainer 0 dimension okuyup `width(-1) height(-1)` warning basıyordu
- Date picker `onChange` her keystroke'ta URL'e yazıyordu → invalid date string → `new Date(...).toISOString()` race condition

**Fix:** `1d4c8e9`

- `<ChartFrame>` shared helper: `error → ErrorMessage`, `loading → Spinner mesajı`, `empty → empty mesajı`. Hepsi `min-h-[Npx]` wrap'inde, böylece Recharts container fresh tab mount'unda non-zero dimension okuyor.
- Date picker'lar local `useState` ile besleniyor; URL commit `onBlur`'da ve `Number.isNaN(d.getTime())` ile validate sonrası. Tutarsız onaylama davranışı bu race ile çakışıyordu.

## Yapılması önerilen işler

### Profiling önce, optimizasyon sonra
1. **`pg_stat_statements` extension** — Postgres init script'e `CREATE EXTENSION` ekle, container restart'ta gelsin.
2. **Worker chunk-level structured log** — bottleneck breakdown'ı log'tan çıkarılabilir hale getir.
3. **py-spy / cProfile entegrasyonu** — geliştirici makinesinde bir batch koşumu için flame graph üret.

### BERT optimizasyonu
4. **BERT batch_size** (şu an 32, modele göre 64-128 daha hızlı olabilir — RAM ↔ throughput trade-off).
5. **Model warm-up cache** — ilk satır cold-start jitter'ı (zaten image'a bake edildi ama mmap pages cold).
6. **Mixed precision (FP16)** — CPU'da etkisi sınırlı, ama torch CPU AMP destekli; deneyle.
7. **ONNX export** — savasy/bert-base-turkish modelini ONNX'e çevir, ONNX Runtime ile %2-4x CPU hızlanma.

### Override pipeline
8. **Erken çıkış** — kategori match yoksa override layers'ı atla.
9. **Cache** — tenant config TTLCache zaten var; kategori-level cache eklenebilir.

### DB / I/O
10. **Bulk INSERT yerine COPY** — chunk commit'inde 1000 satır COPY ile gönder.
11. **Connection pool sizing** — `pool_size` + `max_overflow` worker'ın paralel chunk'ları için tune et.

### UX
12. **Chunk size 1000 → 100** — her ~100 sn'de UI update'i, daha responsive feel.
13. **Mid-chunk progress field** — DB'ye chunk içinde `processed_rows` partial update (transaction commit'siz).
14. **Frontend stale-after-N-fails state** — "Backend hâlâ çalışıyor, son güncelleme N dk önce" mesajı.

### Mimari
15. **GPU host opsiyonu** — 10x+ hızlanma için en hızlı yol; ama maliyet + ops karmaşıklığı (separate VPS, model swap).
16. **Job kuyruğu external (Redis + RQ/Celery)** — şu an APScheduler tek instance; multi-worker için altyapı.

### Observability / hata izleme (eklendi 2026-05-04, Sprint 8.3.6.6 round-3 sonrası)

**API error handler `logger.exception()` zorunlu pattern** — Sprint 9.0 çalışmasından önce halledilmeli.

- **Bağlam:** Sprint 8.3.6.6'da SWOT generate üç round debug istedi (round-1 `minItems`, round-2 `enum without type`, round-3 yeni cür'et). Production'da 500 dönüyordu ama backend log'da traceback YOKTU — root cause her seferinde Gemini API'sinin error response body'sini ayrıca yakalayan SDK katmanına `print()` eklenerek bulundu.
- **Minimum gereken:** Tüm 5xx path'lerinde `logger.exception(...)` (otomatik traceback) + structured fields: `request_id`, `tenant_id`, `user_id`, `exception_type`, route path. FastAPI exception handler middleware ile tek noktada uygulanmalı; tek tek route'ta tekrarlanmasın.
- **Sentry (Sprint 8.6) öncesi:** Sentry SDK'sı tracebacks'i otomatik alır ama o entegrasyon gelene kadar bile minimum stdout'a `logger.exception` çıkması Sprint 9.0 çalışmasının hata-payını öder.
- **Doğrulama testi:** route layer test'inde mock provider 500 fırlatsın → caplog'da traceback satırı bekle.

### LLM model konfigürasyonu (eklendi 2026-05-04, Sprint 8.3.6.6 round-4 sonrası)

**Default model şu an `gemini-2.5-flash` (free-tier zorunluluğu).**

- **Bağlam:** Round-3 fix sonrası SWOT generate hâlâ 500 dönüyordu — sebep `gemini-2.5-pro` Free tier'da quota'sızdı. Tüketici "Google AI Pro" aboneliği API quota'sı sağlamıyor; sadece paid Google AI Studio billing setup gemini-2.5-pro çağrısını izniyor. Default'u `gemini-2.5-flash`'e çevirdik (round-4) — flash mevcut prompt boyunda yeterince hızlı ve free-tier çalışıyor.
- **Pro istenirse:** Tenant'ın Google AI Studio'da billing'i aktif olmalı. API key tenant'a aitse (LlmCredential tablomuz şifreli saklıyor) ve billing aktiftir, gemini-2.5-pro çağrılabilir — sadece default'u değil, **per-tenant model override** lazım.
- **Sprint 9.x roadmap:** Tenant başına `model_name` override (default flash, paid tier'lar pro'ya yükselebilsin). LlmCredential satırına model_name kolonu eklemek bir yol; ayrı bir `tenant_model_preferences` tablo başka bir yol. Karar Sprint 9.x sırasında.
- **DB izi:** Migration 0019 prompt_templates seed'inde `"model": "gemini-2.5-pro"` literal var ama service module-resident default kullanıyor; seed satırı şu an okunmuyor (Sprint 8.3.6.3 kararı). Override sistemine geçince seed/template registry yeniden devreye alınır.

### Observability — Round-6 doğrulama (eklendi 2026-05-04)

**Round-3 not'u (logger.exception zorunlu) doğrulandı.** Round-6 OKR PDF Jinja `UndefinedError`'ı production stdout'una **doğal olarak** traceback'iyle birlikte düştü; root cause sunucu ajanı tarafından tek bakışta tanındı (template hattı + 'str object' has no attribute 'strftime' satırı).

- **Önceki SWOT 500'leri (round 1-3):** Gemini SDK provider katmanında catch ediliyordu → traceback yutuluyor, dış log'da sadece "LLMError" görünüyordu. `print()`'le SDK içine sızılarak debug yapıldı.
- **Round-6:** Jinja exception template render path'inden bubble-up etti — provider/handler katmanı yok, traceback uvicorn stdout'una doğrudan düştü. Sunucu ajan teşhisi 1 round'da tamamlandı.
- **Çıkarım:** Provider/handler katmanlarındaki try/except blokları üzerinden geçen 5xx'lerde `logger.exception(...)` MUTLAKA olmalı. Yutmadan yumuşatma (catch + raise CustomError) iyi pattern, ama logger.exception ile bilgiyi koruyalım.
- **Sprint 8.4 (CI/CD) öncesi:** `services/`, `routes/`, `llm/` katmanlarındaki tüm `try/except Exception` ve `try/except <SubError>` bloklarını gez, her birinde `logger.exception` var mı kontrol et. Yoksa ekle. Bir defalık tarama, 30 dk iş.
- **Sprint 8.6 (Sentry) hazırlığı:** Generic 5xx middleware structured error log + Sentry hook (request_id, tenant_id, user_id, exception_type, route path). Sentry entegrasyonu gelmeden önce minimum stdout'a structured JSON.

### LLM structured response hardening (eklendi 2026-05-05, Sprint 8.3.11 R2 sonrası)

Sprint 8.3.11 R1+R2 deneyimi gösterdi ki LLM-driven endpoint'lerde Türkçe yanıt + token kalibrasyonu + sessiz hata toleransı üç ayrı yüzeyde dikkatli olmayı gerektiriyor. Sprint 9.0 öncesi (veya 8.4 ile beraber) ele alınmalı:

- **Türkçe token şişmesi:** Türkçe UTF-8 + agglutinatif morfoloji aynı içeriği İngilizce'ye göre ~%30-40 daha çok token'da kodlar. Token kapasiteleri prompt-bazlı kalibre edilmeli:
  - SWOT: 8192 (mevcut, OK)
  - OKR: 4096 → büyük tenant'larda risk altında, 8192'ye yükseltme adayı
  - Executive briefing: 2048 → 4096 (R1) → 8192 (R2). Final değer.
  - Future: tenant_size'a göre dinamik (10K+ review için daha geniş).
- **`finish_reason` check zorunlu pattern:** Her structured-output LLM call'ında MAX_TOKENS / SAFETY / RECITATION ayrı exception'lara map edilmeli (`LLMTokenLimitError`, `LLMResponseBlockedError` zaten Sprint 8.3.11 R2'de eklendi). SwotProvider + OkrProvider zaten `_check_finish_reason` üzerinden geçiyor; yeni LLM-driven endpoint eklerken kontrol et.
- **Computed field sanitization:** Server-side hesaplanması mümkün olan field'ları (örneğin `change_pct = (current-prev)/prev*100`) **prompt'a ham bırakmadan** server-side hesapla + LLM'in çıktısının üstüne yaz. LLM `previous=0` div-by-zero ya da NaN'ı bazen "yaratıcı" şekilde tahmin ediyor (Inf%, fabrike sayı). Sprint 8.3.11 R2'de executive briefing'in `kpi_changes` payload'ı bu pattern'e geçti; SWOT/OKR'da benzer alan yok ama gelecekte (örn. cohort change deltaları) aynı kuralı uygula.
- **Gemini SDK deprecated warning:** `google.generativeai` paketi resmen deprecated; `google.genai` paketine migration Sprint 9.x roadmap'inde. Bu sprint'te sadece test compose warning olarak görünüyor, prod'da etkisi yok ama upgrade pencerelerini dar tutmaya başlamak gerek.
